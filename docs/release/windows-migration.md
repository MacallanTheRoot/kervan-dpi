# Windows legacy compatibility and rollback — candidate report

Status: **offline inspection complete; native migration QA pending**. The upgrade strategy is to **reuse the existing configuration file in place**. The source does not call `prepare_config_copy()` at startup and does not rename user data. Existing installation types on user machines are unknown; this repository has a onefile EXE build and no Windows installer or uninstaller.

| Surface | Current source behavior | Upgrade/rollback action |
| --- | --- | --- |
| Old GoodbyeDPI Turkey EXE | Earlier portable `GoodbyeDPI-Turkey.exe` may coexist with `Kervan-DPI.exe`. | Keep old EXE until the branded candidate passes QA. Launch one at a time. Roll back by quitting Kervan DPI and running the retained old EXE. |
| Preferences | `%APPDATA%\GoodbyeDPI-Turkey\config.json` remains authoritative; `ConfigManager` keeps unknown JSON keys. | Back up the file before test; compare values after restart. Do not move or merge automatically. Rollback uses the same path. |
| First-run bundled settings import | `ConfigManager` may read a bundled `config.json` on a fresh profile and exclusively create the legacy AppData file. It does not replace an existing destination; malformed/inaccessible bundled JSON falls back to defaults. This is separate from the dormant Phase 8A helper. | Check fresh and existing profiles separately. Do not interpret a fresh import as a new Kervan data directory. |
| Qt application and organization | Display name becomes Kervan DPI; organization remains `MacallanTheRoot`. | Check native taskbar/window identity; no registry or settings ID migration is planned. |
| Startup | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\GoodbyeDPI-Turkey GUI.lnk` is reused if present; fresh enable creates `Kervan DPI.lnk` there. A newly written shortcut has Kervan DPI description and current EXE target. Disabling startup removes both recognized shortcut names. | Record the existing target and shortcut file first. If it points to the old EXE, update it only after deciding to switch. If both shortcut names exist, Enable refuses the duplicate. Confirm exactly one entry; rollback may require recreating the old target. |
| Engine staging | `%ProgramFiles%\GoodbyeDPI-Turkey\engine\<hash>` remains unchanged. | Record active `goodbyedpi.exe` image path, WinDivert service `BINARY_PATH_NAME`, ownership and ACL. Never delete an old directory solely because a new hash exists. |
| WinDivert service and driver | Upstream service identity stays unchanged; another app may also use WinDivert. | Observe before/after Enable, Disable and Quit; do not forcibly stop/delete a foreign or uncertain service. |
| Start Menu shortcut | No installer-managed Start Menu entry is created by this project. | If a user has an old manual shortcut, inspect/update it manually after QA. Do not remove it automatically. |
| Desktop shortcut | No project script creates or removes a desktop shortcut. | Treat any existing desktop shortcut as user data; inspect its target and leave it alone unless the user chooses to update it. |
| App registry keys / updater | Current project code has no application registry identity, `Run` key, update service or upgrade/uninstall registry entry. The app uses a UAC `runas` launch; the separate WinDivert driver/service can have system state. | Do not infer absence of third-party/manual entries on a real machine. Inventory them during native QA. Do not edit a driver/service entry on the basis of a name alone. |
| Installer upgrade / uninstall | No project installer or uninstaller exists. | Portable removal means quitting the app and removing only the chosen EXE/ZIP after checking autostart. Preserve config and engine staging until a separate safe cleanup design exists. |

## Test report

Offline tests in `tests/test_brand_migration.py` cover fresh/existing shared-path profiles, first-run import, repeat launch, corrupt/inaccessible input, portable removal and rollback fixtures; the dormant opt-in copy helper covers idempotence, conflicting targets, interruptions, concurrent calls, symlink/reparse/hardlink rejection and `..` path rejection. The active upgrade creates no second settings file, so it does not copy, delete or change permissions of existing user settings on launch. A later settings save uses `os.replace`; its effective NTFS ACL and concurrent-writer behavior still require native verification. The dormant copy helper's backup/target permissions and reparse races are **not** certified for Windows production migration; do not activate it for this RC. The [Phase 8B record](../engineering/kervan-phase8b-qa.md) details earlier limits.

Native test pending: use a disposable Windows profile, or a backed-up real test profile only with its owner's authorization. Record before/after config hashes and ACLs, current shortcut target, onefile paths, WinDivert path and process list in the [QA report](windows-native-qa-report-template.md). Test a normal upgrade, restart, rollback to old EXE, portable removal and manual shortcut cleanup. Verify no settings loss, no duplicate startup execution and ordinary HTTPS after Quit. For rollback, Quit Kervan DPI, restore the recorded startup target if it was changed, then run the retained old EXE. Do not enable the dormant new config path or delete either file as part of this candidate.

Verdict: **PENDING native Windows upgrade/rollback QA**. Automatic data-path migration remains deferred and needs its own native coverage and explicit user acceptance.
